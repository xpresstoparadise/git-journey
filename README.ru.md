# Git Journey

[English](README.md) · **Русский**

История командных репозиториев как кино. Ствол растёт снизу вверх по времени, от
него ответвляются репозитории, камера останавливается на каждом шаге команды, а
бегущая по пути звезда разгорается и в конце гаснет. В финале — вся карта года и
вклад каждого.

> получится MP4 демо-команды.

## Зачем это

Обычно история кода — это таблица: коммиты, графики, «+1234 −56». За ней теряется
главное: каждая точка в истории — чьё-то утро, решение, ночь перед релизом. Этот
фильм рассказывает ту же историю как путь.

**Ствол — общее время команды.** Он растёт снизу вверх, от начала периода к
«настоящему». Всё, что происходит в репозиториях, происходит на его фоне.

**Репозитории — дороги, которые от него отходят.** Репозиторий ответвляется в
момент первого изменения и дальше живёт рядом со стволом. Живые проекты бегут
параллельно до самого «настоящего»: их история не закончена. Завершённые
вливаются обратно в ствол: их путь пройден, а сделанное стало частью общего.

**Merge request — маленькая дорога внутри большой.** Ветка уходит в сторону,
по ней проходят коммиты, а потом она вливается обратно. Так выглядит любая работа:
отойти, сделать, вернуть.

**Звезда — это мы, идущие по пути.** Бегущая точка — команда (или один человек, если
выбрать его в списке). В начале пути она светит скромно и роняет редкие искры: всё
только начинается. С каждым месяцем — проекты, люди, опыт — звезда разгорается,
искр становится больше, хвост длиннее. К «настоящему» она горит как бенгальский
огонь, во все стороны. А потом гаснет.

**Погаснуть — не исчезнуть.** Когда звезда гаснет, остаётся карта, и вся она мерцает:
каждая точка горит тем ярче, чем больше в неё вложено. Путь пройден, а след остаётся
— в этом и смысл.

**«Поздравляем!»** Проект, доведённый до конца, — не пропажа из списка, а праздник:
конфетти, имена всех, кто его делал, и ветка торжественно вливается в ствол.

**«Good bye».** Люди уходят: в другие команды, в другую жизнь. Их путь не стирается —
он остаётся на карте, подсвеченный целиком. Прощание не спешит: портрет, слова
человека и пятнадцать секунд тишины. Тот, кто прошёл с командой этот путь,
заслуживает больше, чем строку в логе. Свои прощания человек оставляет сам —
последним коммитом.

**Финал — благодарность, а не соревнование.** Рейтинг в конце не про то, кто
лучше, а про то, кто сколько вложил в общее. И у каждого можно открыть его
собственный путь.

## Быстрый старт

### Готовый бинарник (без Python)

Скачайте файл под свою систему со страницы релизов и положите в пустую папку:

```
git-journey.exe      ← двойной клик
repos/                ← сюда клоны репозиториев (создастся при первом запуске)
photos/               ← сюда фото людей (необязательно)
```

Положите в `repos/` клоны (`git clone …`) и запустите программу — соберутся данные,
откроется браузер. Нужен установленный `git`.

```bash
git-journey                                  # repos/ → фильм в браузере
git-journey local D:/clones --period 2025-2026
git-journey gitlab                           # из GitLab по .env
git-journey serve --lan                      # показать по сети последний собранный фильм
```

### Из исходников: локальные клоны

```bash
python fetch_local.py                 # repos/ → web/data → браузер (http://127.0.0.1:8766/)
python fetch_local.py --lan           # то же, но доступно по сети
start-local.cmd / start-local.sh      # то же двойным кликом
```

Что видно из обычной истории git:

* коммиты с авторами, датами и строками кода;
* **MR — по merge-коммитам**: GitLab пишет в них «See merge request group/proj!12»,
  GitHub — «Merge pull request #12»; коммиты ветки MR — всё между родителями
  merge-коммита. Squash-мерджи видны как обычные коммиты;
* рождение репо — по первому коммиту; метки `Journey:` — из полного текста;
* ссылки на коммиты, если `origin` клона указывает на GitLab/GitHub.

### Из исходников: GitLab

```bash
cp .env.example .env              # GITLAB_URL, GITLAB_TOKEN, GITLAB_PERIOD
python fetch_gitlab.py            # → web/data/gitlab_raw.js (+ .json)
python serve.py                   # http://127.0.0.1:8766/  (LAN: http://<ip>:8766/)
```

Python 3.10+, только стандартная библиотека. Ingest ходит в GitLab **напрямую**:
системный HTTP-прокси игнорируется (`ProxyHandler({})`, `NO_PROXY=*`). Без выгрузки
UI покажет демо-данные; `?demo` — демо-команда всегда.

`python fetch_gitlab.py --period 2025-2026 --branch main` переопределяет `.env`.
Повторный запуск **догружает**: репо, у которых не сдвинулся `last_activity_at`,
берутся из прошлой выгрузки без запросов к API (`--full` — перевыгрузить всё). Открытая
страница раз в 5 минут проверяет выгрузку и предлагает «Обновить». Автообновление по
расписанию — `tools/refresh.cmd` (Windows, `schtasks` внутри) или `tools/refresh.sh` (cron).

Для каждого MR выгрузка забирает его коммиты (`/merge_requests/:iid/commits`) —
в фильме они идут по ветке MR, а не по основной линии.

Firewall (Windows, от админа), если нужен доступ по LAN:

```bat
netsh advfirewall firewall add rule name="Git Journey 8766" dir=in action=allow protocol=TCP localport=8766
```

## Настройки — `journey.json`

Один необязательный файл рядом с программой (или в корне репо) для всего, что не секрет;
шаблон — `journey.example.json`. Любой ключ можно не указывать — будет значение по
умолчанию; параметры URL (`?speed=2&mode=full&lang=ru`) важнее файла.

| Секция | Ключи |
|---|---|
| верхний уровень | `title`, `subtitle`, `language` (`auto` / `en` / `ru`) |
| `film` | `mode` (`highlights` / `full`), `speed`, `highlightStops`, `cardMinSeconds`, `farewellSeconds`, `sparks`, `sparkler`, `grain`, `confetti`, `accent` |
| `ranking` | очки за `commit`, `mr`, `newRepo` |
| `ingest` | `groups` (группы GitLab вместо «все мои проекты»), `include` / `exclude` (маски путей), `excludeAuthors` (боты), `aliveDays`, `maxMrCommits` |

Настройки фильма подхватываются при каждом `serve` и выгрузке — перевыгружать не нужно.
Секреты (`GITLAB_TOKEN`) остаются в `.env`.

## Язык

Интерфейс на английском и русском: по умолчанию — язык браузера, дальше `language` в
`journey.json`, `?lang=en|ru` или кнопка EN/RU в шапке (запоминается). Демо-команда тоже
переключается.

## Фото участников

Два источника, оба работают и вместе:

* **папка `photos/`** — файл называется именем человека (в любом написании, которое
  знает склейка авторов), e-mail из коммитов или логином:
  `Ирина Савельева.jpg`, `isaveleva@corp.example.png`, `isaveleva.webp`.
  Форматы jpg/png/webp/gif/svg, до 5 МБ. **Фото из папки важнее аватарок GitLab**;
* **GitLab** — `fetch_gitlab.py` скачивает аватарки: `avatar_url` авторов MR и владельцев
  репо, для авторов коммитов — `GET /api/v4/avatar?email=…` (`--no-avatars` — пропустить).

Всё складывается в `web/data/avatars/`, браузеру не нужен доступ к GitLab (LAN, запись
видео). Нет фото — инициалы.

**Иконки репозиториев** на карточках, по старшинству: свой файл
`photos/repos/<имя репо>.png` (jpg/png/webp/gif/svg); аватарка проекта из GitLab; для
локальных клонов — логотип из самого репо (`logo.svg|png`, `icon.*`, `avatar.*` в корне,
`.gitlab/`, `.github/`, `assets/`, `docs/`, `images/`, `static/`, `public/`). Нет иконки —
плитка с первой буквой репо в его цвете.

## Управление

| Клавиша / жест | Действие |
|---|---|
| Пробел | пауза / дальше |
| M | «Главное» (~1.5 мин, только ключевые моменты) ↔ «Полностью» |
| клик по шкале внизу | перемотка на эту неделю |
| P | режим «Кино»: полный экран, кинорамка, субтитры |
| кнопка «Запись» | меню форматов → показ с начала в режиме «Кино» → видеофайл |
| 1 · 2 · 3 | скорость 1× · 2× · 4× |
| F / End | сразу к финалу |
| R | сначала |
| колесо, drag | осмотреться (показ встаёт на паузу) |
| клик по узлу | карточка события со ссылкой в GitLab |
| клик по автору в финале | подсветить его путь на карте |

URL-параметры: `?period=2026&speed=2&mode=full&person=Имя`, `?demo` — демо-команда,
`?debug` — оверлей с fps, размером мира и DOM и счётчиком визитов, где ветка оказалась за
краем экрана (пришлите скриншот, если что-то не так на большой команде).

## Запись видео

Кнопка «Запись» → формат:

| Формат | Для чего | Что пишется |
|---|---|---|
| Экран 16:9 | презентация, YouTube | весь показ в текущем режиме и скорости, до 1920×1080 |
| Telegram 9:16 | вертикальное видео, сторис | «Главное» на 1.5×, до 1080×1920 |
| Квадрат 1:1 | пост, чат | «Главное» на 1.5×, до 1080×1080 |

Браузер спросит, можно ли захватить вкладку — выберите эту вкладку. Для 9:16 и 1:1
сцена на время записи становится вертикальной/квадратной колонкой: карточка —
компактной полосой снизу, подписи — субтитрами. В файл попадает ровно кадр сцены.
Запись останавливается сама после финала; раньше — `Esc` или кнопка ещё раз.

* **MP4 (H.264)** — Chrome/Edge 126+: Telegram и телефоны играют сразу.
* Иначе **WebM** — Telegram примет как файл.
* Разрешение = пиксели сцены на экране: для чёткой вертикали — монитор повыше.

## Особые моменты: «Поздравляем!» и «Good bye»

Команда сама отмечает последний коммит (или MR) строкой в сообщении коммита
или описании MR — фильм остановится и сыграет сцену:

```
Journey: finish  Передали в эксплуатацию     → «Поздравляем!», конфетти, команда проекта;
                                                 репо закрывается и вливается в ствол
Journey: goodbye Спасибо, команда!            → «Good bye, <автор>», портрет, итоги, его путь на карте
```

Текст после метки — подпись в сцене (необязательно). Короткие формы:
`#journey-finish`, `#journey-goodbye`. Свои шаблоны — `LIFEWAY_FINISH_RE` /
`LIFEWAY_GOODBYE_RE` в `.env` (регулярные выражения Python). Такие коммиты никогда
не выпадают при прореживании. Посмотреть: `/?demo`.

Если меток несколько, сцена играет **один раз — по последней**:

* `goodbye` — последний по дате коммит/MR с этой меткой у человека во всех репо
  (с учётом склейки написаний имени из `authors.json`);
* `finish` — последний такой коммит/MR в пределах проекта.

Более ранние метки показываются как обычные коммиты — ошибочную или преждевременную
метку можно «перекрыть», просто поставив новую позже.

## Путь одного участника

Список «Участник» в шапке (или `?person=Имя`): остановки только там, где есть его
изменения, чужое приглушено. Играет только его собственное прощание и
«Поздравляем!» только тех проектов, где он работал. В финале — его карточка:
строки кода, коммиты, MR, репо и доля в общей работе.

## Авторы: один человек — одно имя

Ingest склеивает написания автоматически: одинаковый e-mail коммитов, одинаковый
логин, `Lena_Frost` = `Lena Frost`. То, что так не склеить
(`Elena Morozova` ↔ `Елена Морозова`), задаётся в `web/data/authors.json` — формат
в `web/data/authors.example.json`. UI читает этот файл на лету, перевыгрузка не нужна.

`python fetch_gitlab.py --suggest-authors` (или `git-journey suggest-authors`)
подсказывает пары по транслитерации и перечисляет логины без полного имени.

Инварианты раскладки (их проверяют тесты):

* **Ось времени неравномерная.** Неделя — одна полоса по высоте для всех веток.
  Внутри ветки узлы стоят с фиксированным минимальным шагом, поэтому подписи
  не наезжают, а параллельные репо остаются синхронными по времени.
* **Слоты веток постоянные.** Ветка живёт в своём слоте до конца. Слот
  переиспользуется только после того, как прежний владелец влился в ствол,
  поэтому ветки не уезжают и не слипаются. Подписи всегда стоят снаружи ветки.
* **Камера кадрирует в безопасную зону**, то есть в окно минус открытые панели.
  Карточка встаёт с противоположной от ветки стороны и не может её закрыть.

## Сборка бинарника

GitHub Actions (`.github/workflows/build.yml`) на каждый push гоняет тесты и собирает
PyInstaller-бинарники под Windows, Linux и macOS (артефакты сборки). Тег `v*`
(`git tag v1.0.0 && git push --tags`) создаёт релиз с бинарниками.
Бинарник для macOS не подписан: при первом запуске — правый клик → «Открыть».
